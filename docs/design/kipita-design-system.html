Make the phone match the road.

The web app already has a mature look: cream paper, deep green ink, one orange action. The mobile app drifted from it. This is the design system that closes the gap, with every token, component and screen read out of the two codebases and written so it drops into Compose Multiplatform or the Expo build the team ships today.

Web appMobile app

One canvas

Web uses cream paper with white cards. Mobile uses a sage canvas. Mobile moves to cream, light and dark.

Search rides

The orange (lime in dark) is the web app's primary action. Mobile has no equivalent yet, so every button is green.

01 · Principles

Five rules the rest of this follows

Taken from apps/web/PRODUCT.md, because they describe the product, not the platform. Where a later decision looks fussy, one of these is the reason.

Phone first, outdoors, in a hurry

Drivers publish from a parked car in daylight. Targets are 48dp, text is 12sp or larger, inputs are 16sp, and contrast clears 4.5:1 for anything you read.

One action per screen

Exactly one orange (lime in dark) button. Search rides, Pay with M-Pesa, Publish ride. Everything else is green, tonal or outlined.

Money is explicit

Always KES 1,200. Always say what you pay, what the driver earns, and where the money is right now (held in escrow, or released).

Specifics beat decoration

A ride is two towns, a real time and a real plate. The route and the plate are the largest things on a card; illustration is never the hero.

Claim only what you can prove

No invented ratings, counts or testimonials. Status is never colour alone: icon plus word. No emoji in the interface; icons only.

Web is the reference

Where the two apps disagree, web wins unless there is a measured reason (touch size, grid, contrast). Each exception is marked.

04 · Foundations · Typography

Typography

Web pairs a geometric heading face with a friendly text face. Mobile uses only the text face. The fix is two families and a rule for which does what: Manrope names things, DM Sans is read and operated. Both fonts are embedded in this file from apps/web/public/assets.

Headings · numbers · route names
Manrope

Bold 700 and ExtraBold 800. Screen titles, sheet titles, section headings, every amount and time, the wordmark.

Reading · labels · controls
DM Sans

Regular 400, Medium 500, SemiBold 600. Body, helper text, buttons, chips, field text, tab labels.

Scale

Role names are Material 3's, so they map one-to-one to Compose's Typography. Sizes are sp, so they scale with the user's system font size. Nothing is below 12sp. Mobile keeps the finer M3 steps because a phone list is dense.

Amounts and times

Manrope with tabular figures (tnum) so a column of fares aligns. KES 1,200 · 6:30 AM

Anything typed is 16sp

Below 16, iOS zooms the page on focus. This is already fixed in mobile (typography.input) and stays.

Two styles retire

caption (10) is removed and labelSmall goes from 11 to 12. Tab labels move from 10.5 to 12.

05 · Foundations · Layout, shape, depth

Space, shape and depth

Spacing

4pt grid, unchanged from mobile and web (which already share it). The screen gutter is 16. Content that scrolls under the floating tab bar needs 112 of bottom clearance.

Radius

Kept from mobile because it sits on the 4pt grid. Web's CSS variables (--r-sm and friends) are already overridable, so web can converge later.

Elevation

Tone first, shadow second. Use a shadow only for things that float over content. Android values are Compose shadowElevation in dp.

Touch targets

The glyph can be 40, the hit area is 48. Mobile's 36px icon buttons grow to 40 and gain a 48 target; chips become 32 tall with the same 48 hit area.

40 visual · 48 hit area

Dashed line is the tappable area.

06 · Foundations · Motion

Motion

Web already ships Material's easing and duration tokens; mobile hard-codes 150 to 200 ms. Adopt the tokens so a press feels the same on both. Hover a card to play its curve.

Durations

Press feedback 100 to 150, state changes 200, sheets and cards entering 300 to 400. Nothing past 500.

Rules

Press scales to .97 on buttons and .98 on cards. Success may overshoot (spring); nothing else bounces. With reduced motion on, drop every transform and keep colour fades only. Status flow dots stop flowing.

10 · Rules · Voice and formats

Say it plainly, format it the same way

Web already writes in sentence case with real numbers. Mobile's strings are Title Case. Switching them is a one-file change in lib/i18n/en.ts.

Messages

Say what happened, to whom, with the real place names and amount. No exclamation marks, no emoji.

Seat confirmedWanjiru M. has your seat for Nairobi to Nakuru, today at 5:30 PM.
Payment still pendingApprove the M-Pesa prompt on your phone to confirm your seat.
Payout sentKES 1,056 is in your wallet after the 12% fee on a KES 1,200 fare.

Do

  • Name the towns, the time and the amount.
  • Say where the money is: held in escrow, or released.
  • Put the next step in the button: Send M-Pesa request.
  • Use icons for reactions and status, plus a word.

Don't

  • Invent ratings, trip counts or testimonials.
  • Use emoji in interface text, or Title Case on buttons.
  • Write "Submit", "OK" or "Oops!" when you can name the action.
  • Colour a status without an icon and a word beside it.
11 · Rules · Accessibility

Built for a phone in the sun

Targets WCAG 2.2 AA. The ratios below are computed from the hex values in this system. The table shows what mobile has today next to what it becomes.

PairTodayThis systemResult
Tertiary text on canvas3.57 · outline as text4.97 · mutedText on creamFixed
Field border on white1.44 · outlineVariant4.15 · outlineFixed
Muted text, darkn/a7.43 on nightNew
CTA label, lightn/a4.91 ink on orangeNew
CTA label, darkn/a11.78 deep green on limeNew
Orange button vs creamn/a2.69 fill against canvasKnown the label names the button
Amber alert on cream2.48 if used as textColour on icon well and 4px edge onlyRule
White card on creamn/a1.08Rule always a 1dp border

The orange button is below 3:1 against cream, so it is never the only thing that says "this is a button": it always has a verb label at 4.91:1 and a pill shape. Meaning is never carried by colour alone, and every line of text is at 4.5:1 or more.

Seeing

Text sizes are sp and scale with the system setting; check every screen at 200%. Nothing under 12. Status is icon, word and colour. Dark mode gets its own contrast pass, not an inversion.

Touching

48dp minimum targets with 8dp between neighbours. Chips and icon buttons grow their hit area, not their look. No gesture is the only way to do something.

Hearing and reading aloud

Every icon button has a label that names the action. Errors are announced when they appear and tied to their field. Reading order follows visual order, and the sheet traps focus.

Motion

Honour the system reduce-motion setting: drop scale and slide transitions, keep colour fades, stop the live pulse and the flowing dots.

Money and trust

A payment screen always shows the total, where the money goes and how to stop. Never a countdown, never a pre-ticked add-on.

Before shipping a screen

One cta. Targets at 48. Contrast table clean in both themes. Works at 200% text. Works with the screen reader on. Has an offline and empty state.

@Composable
fun KipitaTheme(darkTheme: Boolean = isSystemInDarkTheme(), content: @Composable () -> Unit) {
    CompositionLocalProvider(
        LocalKipitaColors provides if (darkTheme) KipitaDarkExtended else KipitaLightExtended
    ) {
        MaterialTheme(
            colorScheme = if (darkTheme) KipitaDarkColors else KipitaLightColors,
            typography = kipitaTypography(),
            shapes = KipitaShapes,
            content = content,
        )
    }
}

Sized small, medium or large. Each step ships on its own and leaves the app consistent.

  1. Retheme: colours and typeSwap the surface and outline values, add cta, onCta and mutedText, and load Manrope and DM Sans with expo-font. Run the app: most screens improve with no component change.
    Small
  2. Button: add cta and hit areasNew variant, hitSlop on small and medium, and chips at 32 tall. Make the search go button, Pay, Publish and count badges use it.
    Small
  3. Fix the two contrast failuresPoint textTertiary at mutedText and the field border at outline. Both are single lines.
    Small
  4. Sentence-case the copyOne pass through lib/i18n/en.ts, and fix formatCurrency to use en-KE.
    Small
  5. Swap Ionicons for the Kipita setBuild one Icon from the web glyphs with react-native-svg, keyed by the mapping in Icons. Draw the four missing glyphs first.
    Medium
  6. Move hard-coded colours into tokensAlert categories, the tan and jungle values, and the verified badge.
    Small
  7. Screen pass and dark QAHome, Ride, Trips and Wallet first, then the rest. Check each at 200% text and in both themes.
    Medium

Decisions still open

Reactions

Mobile has four emoji reactions; web has a heart. This system draws reactions as icons. If community wants the emoji set, confine it to user text, not controls.

Radius on web

Web's radii (11, 14, 22, 30, 36) are off the 4pt grid. Mobile's stay. Web's variables are overridable, so web can converge later with no redesign.

Kotlin

If the team moves to KMP, the Compose tabs are ready. HCT for vehicle-tinted cards needs a library such as MaterialKolor.

Four glyphs to draw

CaretUp, CloudOffline, Backspace and Fingerprint, at 24 grid, 1.75 stroke, with a solid variant where the set has one.
